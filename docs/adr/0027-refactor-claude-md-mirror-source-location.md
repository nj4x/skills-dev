# Satellite files mirror the source CLAUDE.md location

Satellite files generated by the refactoring skill are written relative to the source CLAUDE.md, not the current project root. If the source is `~/.claude/CLAUDE.md`, satellites go to `~/.claude/docs/agents/`; if the source is `<project>/CLAUDE.md`, satellites go to `<project>/docs/agents/`.

## Rewritten root must wire the satellites via @import

Writing satellites next to the source is only useful if agents actually load them. The mirrored location by itself does **not** guarantee discovery — nothing auto-loads `docs/agents/`. Therefore the rewritten root CLAUDE.md **must** reference every satellite it produced through an explicit `@import` (or the equivalent include directive the runtime honors), using paths relative to the root CLAUDE.md. The skill verifies, before finishing, that each satellite it wrote has a corresponding `@import` line in the rewritten root; a satellite with no inbound import is treated as an error, not a silent omission.

This linkage was validated for the global case: satellites under `~/.claude/docs/agents/` are only loaded because the rewritten `~/.claude/CLAUDE.md` `@import`s them — the directory is not scanned implicitly. The design does not commit to the global location on the assumption that the folder is auto-discovered; it commits to it because the global root imports it.

## Re-runs are destructive: back up before overwrite

Because satellites live next to the source and re-runs overwrite them (and the root) silently by default, any manual edits a user made to the generated output would be lost. This is especially dangerous because ADR-0026 makes re-running the *only* course-correction for essentials, pointing users straight back at these files.

To make this safe, before writing any output the skill takes a **timestamped backup** of the current root CLAUDE.md and the entire `docs/agents/` satellite set (e.g., `docs/agents.bak-<timestamp>/` and `CLAUDE.md.bak-<timestamp>`). The summary report records the backup location. The skill also documents, in the report and in its own docs, that **re-runs are destructive and the supported way to change output is to edit the source and re-run — not to hand-edit generated files.**

## Considered Options

An alternative was always writing to `<project>/docs/agents/` regardless of source path. This fails when refactoring the user-global CLAUDE.md, which has no "project root" to write to — and mixing global instructions into a project docs folder would be confusing.

A silent-overwrite-with-no-backup option was rejected: combined with the mirror-source location and the essentials re-run loop, it clobbers exactly the files the design tells users to re-run against. The timestamped-backup approach was chosen over a full diff-preview gate to keep the skill autonomous while still making destruction recoverable.

## Consequences

The skill must infer the output directory from the resolved source path at runtime. A user refactoring a deeply nested CLAUDE.md (e.g., a sub-package) will get satellites inside that sub-package's directory tree, and the rewritten sub-package root will `@import` them from there. Backups accumulate under timestamped paths until the user cleans them up.
