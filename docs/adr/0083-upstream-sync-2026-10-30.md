## Context

ADR-0078 named upstream `c20facd` as the next baseline, but `c20facd` never reached upstream `main`: it sits only on `origin/wizard-bash32-apostrophe`, and its merge-base with `a496f55` is `49dd158`. skills-dev already carries its wizard fix, so the effective window on upstream `main` is `49dd158..a496f55` — six non-merge commits (`5beb35b`, `ed0de59`, `59db609`, `7739eae`, `d1478fc`, `a496f55`). `docs/research/upstream-skills-diff-2026-10-30.md` classifies each change; this ADR records the decisions taken on it.

## Decision

1. **Port** into `setup-skills` (`ed0de59`, `59db609`):
   - GitHub seed doc: **Blocking** moves into Conventions with the `gh` 2.94+ `--blocked-by` / `--add-blocked-by` forms, keeping the `gh api` form and the `Blocked by:` line as fallbacks; a new **Count open blockers** operation; the Wayfinding **Blocking** and **Frontier query** entries point at them. Existing bold labels stay unchanged.
   - GitHub seed doc: **Close** posts the comment with `gh issue comment`, then runs `gh issue close` (`close --comment` drops the comment on an already-closed issue).
   - GitHub seed doc: **Read a PR** runs `gh pr view`, then `gh pr view --comments` (off a TTY, `--comments` omits the body).
   - Section A (new text on this branch): wire up and verify a reachable remote before recording a GitHub or GitLab tracker; if it cannot be verified, setup stops and tells the user what is missing.
   - skills-dev's own `docs/agents/issue-tracker.md` takes the same GitHub fixes in the same change.
2. **Adapt**:
   - GitHub seed doc: check `gh repo view --json nameWithOwner` before the first `gh issue create` of a session and confirm with the user when it is not their repo; upstream's sentence naming `mattpocock/skills` is dropped (`59db609`).
   - GitLab seed doc, Wayfinding section only: a child ticket is linked with `--linked-issues <map> --link-type relates_to`, and the frontier query takes the map's children as the union of its links (`glab api projects/:id/issues/<map>/links`) and the issues whose description starts with `Part of #<map>`. The union keeps children made before this change, and tickets attached by the `to-tickets` fallback, in the frontier. The Conventions entry **Attach an issue to a parent issue** is untouched, so the `to-tickets` pass 3 fallback to `Part of #<parent>` holds (`ed0de59`).
   - `implement-spec`: a fresh `general-purpose` implementer per ticket and a fresh integration fixer, never `"fork"` and never an earlier implementer resumed with `SendMessage`. The merger stays reusable, matching upstream's final call (`a496f55`): it only merges a committed branch and carries no ticket reasoning into the next task; upstream made it fresh and then reverted that. Upstream's harness-neutral "fresh context window" sentence is not ported.

     ```mermaid
     sequenceDiagram
         participant Orchestrator
         participant Implementer as Implementer (fresh per ticket)
         participant Merger as Merger (reusable)

             Orchestrator->>Implementer: new general-purpose agent, ticket brief
     ```

     No arrow resumes an Implementer with `SendMessage` or forks one.
   - `wayfinder`: the research dispatch declares `subagent_type: "general-purpose"` (`7739eae`). Apart from `implement-spec` (above), the other dispatch sites `7739eae` touched (`code-review`, `codebase-design`, `improve-codebase-architecture`, `research`, `grilling`) already declare a type.
3. **Keep** `glab mr list -F json`. Upstream changed it to `-O json`, but glab's own `mr list` docs list only `-F, --output text|json`; `-O` is the `issue list` flag.
4. **Skip** the legacy `CONTEXT.md` rename offer (Section D already covers it), the issue forms and `CONTRIBUTING.md`, the domain-modeling docs FAQ fix, the version bump and changesets, `chief-of-staff` (ADR-0078 §4), and the omission of `## Blocked by` from tickets (ADR-0078 §3).

## Considered Options

- Take upstream's `glab mr list -O json`: rejected; it contradicts glab's documentation for `mr list`.
- GitLab frontier from `relates_to` links only (upstream's form): rejected; children made before this change, and `to-tickets` fallback tickets, carry only `Part of #<map>` and would drop out of the frontier silently.
- Backfill a `relates_to` link onto every existing GitLab child: rejected; it needs a migration step in every repo, while the union query needs none.
- Have `implement-spec` and `to-tickets` pass 2 cite **Blocking** / **Count open blockers** by name: deferred. It adds dependency contracts to `docs/agents/skill-dependencies.md`, beyond a straight port.

## Consequences

- The GitLab flags (`--linked-issues`, `--link-type`, `glab api … /links`) the kept `glab mr list -F json`, and the frontier's `Part of #<map>` description lookup rest on glab's main-branch docs alone and are untested on a real install. Follow-up: verify all of them against a real glab install.
- Out of scope, separate follow-up: ADRs 0056-0067 and 41 of 74 `.scratch/*/spec.md` and `.scratch/*/issues/*.md` files lack lineage-rules frontmatter; retrofit via `/setup-lineage`, not on this branch.
- `chief-of-staff`'s "write history, not the present" rule (date each claim, cite the commit it was true at) has no host skill today; noted as inspiration only.
- Repos set up earlier keep the old lines in their own `docs/agents/issue-tracker.md` until they rerun `/setup-skills`.
- The next sync baseline is upstream `a496f55`; the next assessment starts from `git log --no-merges a496f55..HEAD`. `c20facd` stays a skills-dev-only fix until upstream merges it in some form.
